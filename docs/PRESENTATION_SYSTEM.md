# سیستم ارائهٔ فاز اول رهجو

## جهت بصری

رهجو باید در نگاه اول یک سیستم کاری جدی و آرام به نظر برسد: وب‌سایت عمومی روشن و شفاف، و کنسول داده‌محور با Sidebar سرمه‌ای. تصویر محصول با جدول، صف اقدام، وضعیت و خط زمانی ساخته می‌شود؛ نه با کارت‌های تزئینی و متن‌های شعاری.

چهار کانسپت مبنا در `docs/design-concepts/` نگه‌داری می‌شوند: خانه، داشبورد، پروندهٔ مشتری و جزئیات درخواست.

## توکن‌ها

- Navy: `#0B1D33` برای ساختار و اعتماد
- Teal: `#0FA3B1` برای اقدام اصلی و وضعیت جاری
- Amber: `#F5A623` فقط برای توجه و هشدار
- Surface: سفید واقعی و خاکستری بسیار روشن
- Border: `#DDE6EB`
- Typeface: Vazirmatn برای متن و کنترل‌های فارسی
- Radius: کم و کنترل‌شده؛ 8 تا 12 پیکسل در محصول
- Shadow: کم‌عمق؛ فقط برای تمایز لایه یا منوی باز

## قواعد رابط

- RTL واقعی: Sidebar کنسول سمت راست و حرکت منوی موبایل از راست است.
- صفحه‌های کاری table/list-first هستند و KPI فقط برای خلاصه‌سازی استفاده می‌شود.
- هر درخواست یک وضعیت، مسئول و «اقدام بعدی» روشن دارد.
- Amber رنگ برند ثانویه نیست؛ فقط هشدار و نیاز به توجه را نشان می‌دهد.
- یک بنر ثابت در بالای کنسول، دمو بودن داده را اعلام می‌کند؛ برچسب‌های تکراری ممنوع‌اند.
- وضعیت‌های موفق، در جریان، منتظر و خطر از نظر رنگ و متن مستقل‌اند.
- نقاط شکست اصلی 980 و 720 پیکسل‌اند؛ جدول‌ها اسکرول محلی می‌گیرند و صفحه overflow افقی ندارد.

## مسیرهای ارائه

مسیر عمومی پیشنهادی:

`/ → /product → /services → /how-it-works → /login`

مسیر محصول پیشنهادی:

`/dashboard → /customers/detail → /requests/detail → /request-service`

سناریوی تعاملی اصلی:

`ثبت درخواست → تکمیل مدارک → پرداخت نمایشی → تخصیص → تحویل → سابقهٔ مشتری`

## قرارداد داده و ادعا

- تمام نام‌ها، مبالغ، KPIها و رویدادها نمایشی هستند.
- پرداخت واقعی، آپلود واقعی، ارسال پیام، API و احراز هویت واقعی وجود ندارد.
- هیچ متن عمومی نباید قابلیت یا اتصال اثبات‌نشده را القا کند.
- قابلیت‌های آینده مثل AI فقط می‌توانند به‌عنوان امکان توسعه معرفی شوند، نه شرط استفاده.
